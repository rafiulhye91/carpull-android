What it is: Android app over the NHTSA vPIC API: https://vpic.nhtsa.dot.gov/api/
browse car makes and their models, edit them locally, add your own, search and sort them.

Stack: Kotlin, Compose + Material 3, Room, Retrofit/Gson/OkHttp, Hilt, Coroutines/Flow, Navigation Compose.

Architecture: MVVM: view -> presentation -> repositories -> data/local(db) + data/remote(API)

Source of data: Room is the source of truth. Screens observe a Room Flow, the API only
writes into Room and lets the flow re-emit. Nothing renders straight off a
network response.

The data handling mechanism: the local-first decision: every row has an
autogenerated localId and a nullable remoteId (the vPIC id). That's what
lets user-created records and API records live in the same table. Models link to
their make by makeLocalId, not makeRemoteId, because a user-created make has
no remote id. Deletes on makes are soft (isDeleted = true), so the next sync
doesn't resurrect them. Sync only happens automatically when the cache is empty; 
there's no manual refresh yet.
